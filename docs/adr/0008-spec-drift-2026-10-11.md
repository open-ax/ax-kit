## Decision

Answers to the three drift questions:

1. **IDL surface we implement — no.** Names, arity, and types are unchanged.
2. **Pinned draft date — yes.** The header moved 2 October 2026 to 9 October
   2026, so `SPEC_VERSION`, every README pin, the conformance baseline pin, and
   the release note move to `9 October 2026` / `d0e4e0e` in the same change as
   the baseline hash. No public name is renamed; that would be an upstream
   discussion at `webmachinelearning/webmcp`, never a local edit.
3. **Conformance baseline — yes.** The error taxonomy is normative text this
   implementation depended on, and the code now follows it. The expected-failure
   lists are re-derived on every engine in the same change.

Record the live hash `195f461ed18629954608e19a5672c4ef8544440e0cefc397d90fe26282dbd175`
as the new baseline, superseding both the issue-reported hash and the live value
at triage time.

### The error mapping, stated plainly

Upstream #339 replaces every `UnknownError` the draft contained:

- foreign traversable → `InvalidStateError` (was `UnknownError`)
- origin mismatch, unknown tool, not exposed → `NotFoundError` (was
  `UnknownError` each; the three share one name so a cross-origin caller cannot
  probe origins or enumerate private tools with fabricated dictionaries)
- `completionSteps` boolean → tool-execution-error enum: `tool not found` →
  `NotFoundError`, `invalid input` → `DataError`, `tool rejected` and
  `unserializable result` → `OperationError`, `target document unloaded` →
  `AbortError`
- target-destroyed cleanup `false` → `target document unloaded` (`AbortError`)

This implementation maps the same way, with two polyfill-side decisions that
the draft does not dictate and that are recorded here rather than left implicit:

- A malformed `RegisteredTool` whose `window` is not an object is a WebIDL
  conversion failure and rejects with `TypeError`. A genuine `Window` whose
  document is unreadable (cross-origin `WindowProxy`) is a valid dictionary
  that fails the exposure outcome, and rejects with `NotFoundError` so a
  fabricated handle cannot probe the target.
- A target that fails its own gates at invocation time rejects with
  `NotFoundError`, indistinguishable from a missing tool, per the existing
  comment in `registry.ts`. Schema mismatches against the stored schema reject
  with `DataError`; that validation is ours (the draft re-reads existence
  only), and `DataError` is the input-side family.

`unknownError()` is deleted. The live draft contains zero `UnknownError`
references.

### Why the pin moves to `d0e4e0e`

It would be defensible to pin `b206dae` (the normative change) rather than
`d0e4e0e` (typos and biblio on top), so the reason is written down.

`SPEC_VERSION.commit` is the revision whose **text** this implementation
implements, and the published document carries `d0e4e0e`. Pinning `b206dae`
would name a revision the published document has already moved past, and a
reader comparing the pin with the live header would find a different date for
no behavioural reason. The typo fixes change no normative algorithm, so the pin
and the code still describe the same event.

### The suite lag, stated plainly

No WPT commit names #338 or #339; `master` still asserts `UnknownError` where
the draft now requires specific names, and still ships the 25 declarative
files the draft deleted. `WPT_SHA` therefore stays at
`fe52996d4465f23617bce91927bdd58e6ce8f541` until a suite revision carries the
same change. The five subtests that fail for exactly this reason are listed as
`upstream-gap` under the `suite-still-asserts-unknown-error` cause — the fix
belongs in the proposal's suite, not here. The declarative exclusions are kept
but reworded: the reason is now removal (#338), not a TODO placeholder.

## Consequences

- `SPEC_VERSION` moves with the re-date; the error taxonomy follows the new
  draft in the same commit.
- `WPT_SHA` does not move. The next drift triage that finds a suite revision
  naming #339 moves it and drops the five `upstream-gap` entries.
- The measured result is re-derived on every engine in the same change
  (Chromium 153.0.8010.12, Firefox 155.0, WebKit 26.6).
- Issue #20 can be closed. The baseline is recorded, the code follows the
  draft it names, and the reason is here.

## Revisit when

- A WPT revision carries #339 and/or removes the declarative files. Then the
  pin moves, the five entries drop, and the exclusion list shrinks.
- The proposal's Bikeshed pipeline starts folding `index.bs` content out of the
  published document, or starts including linked explainers in the output. Then
  a hash change would no longer be safely triaged by comparing `index.bs`, and
  the triage procedure needs a different instrument.

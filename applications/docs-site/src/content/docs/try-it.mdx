## What you are looking at

Five tools, registered through `@ax-kit/core`'s published entry points and
enumerated through the draft's own `getTools()`. The table is what an agent sees:
the same names and the same argument shapes as the
[reference storefront](https://github.com/open-ax/ax-kit/tree/main/applications/demo-store),
so the vocabulary is identical across this project.

The buttons invoke tools through `executeTool`. Two of them send deliberately
malformed arguments.

## Three things worth noticing

**The result is a string.** `executeTool` resolves to `Promise<DOMString>` over a
JSON serialization, so a handler returning `{ tool: "…" }` comes back as
`{"tool":"…"}` with quotes. The caller parses it. This is the specification's
behaviour, not a limitation of the polyfill.

**Both refusals above come from schema validation, not from a throwing
handler.** The library checks the arguments against the declared `inputSchema`
before `execute` runs. This library reports the failure as
`UnknownError`. So an agent sending `query: 42` and an agent sending no `query` at
all both see `UnknownError` and cannot tell them apart. That is a limitation worth
seeing rather than a conformance claim: this schema-refusal mapping is library
behavior.

A handler that throws produces the same `UnknownError`, so a readable message from
your handler reaches your log and not the agent. If an agent must distinguish
"bad arguments" from "the tool failed", validate before invoking.

**One tool is consequential and four are not.** `proceed_to_checkout` spends money
and cannot be undone. The two cart mutations are reversible and cost nothing. A
user who clicked *add to cart* has already confirmed it. Over-annotating trains
everyone to dismiss confirmations, which is the failure mode the annotation exists
to prevent. [Why, in more detail →](/reference/annotations/)

## If nothing happened above

The tool surface is gated behind a Permissions Policy feature, so a document has to
declare that it allows it:

```
Permissions-Policy: tools=(self)
```

Without that header the example appears to work on a development machine and
silently does nothing in a deployment. Most browsers outside the proposal's origin
trial have no native support, so the demonstration installs the polyfill itself
and stands down rather than replacing a native implementation where one
exists.
